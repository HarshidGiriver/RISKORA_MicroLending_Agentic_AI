# ML pipeline

The pipeline is an explicit offline training process plus a read-only inference service. Starting RISKORA loads saved artifacts; it does not regenerate data or train automatically. The current dataset is synthetic and does not establish real-world lending performance.

## Data origin and target

`ml/generate_data.py` generates 12,000 rows using a fixed seed of 42. The 18 CSV columns consist of `LoanID`, 16 borrower/loan predictors and `Default`. Numeric values and categories are sampled from programmed distributions; the default label is also generated by programmed risk assumptions and randomness. There is no observed bank repayment history or independently verified customer sample in this dataset.

`Default=1` means the synthetic positive class; `Default=0` means the synthetic negative class. The target does not define a validated real-world default horizon such as 90 days past due within a year. Any deployment must first define and collect the intended outcome.

## Reproduction commands

Use the pinned Python environment from README. Run these only when intentionally creating a new data/model revision:

```bash
python -m ml.generate_data
python -m ml.train
python run.py --check
python -m unittest discover -s tests -v
```

Generation and training overwrite project data/artifacts. Preserve the existing revision first, perform experiments in a separate checkout and review resulting metrics before accepting changes. Seeded code makes the procedure repeatable under a matching environment; bit-for-bit output across different numerical libraries or platforms is not guaranteed.

## Split and feature preparation

The training script uses stratified train/validation/test splits with random state 42: 8,400 training rows, 1,800 validation rows and 1,800 test rows. The test set is held aside from candidate fitting. The data is synthetic and independently sampled; this split is not a substitute for temporal or external validation on real lending cohorts.

The 16 original predictors include nine numeric inputs and seven categorical inputs. Two derived numeric inputs are added:

```text
LoanToIncome = round(LoanAmount / max(Income, 1), 4)
MonthlyBurdenRatio = round((LoanAmount / LoanTerm) / max(Income / 12, 1), 4)
```

Income is annual, and term is months. MonthlyBurdenRatio is a principal-only burden proxy; it is not an amortizing EMI-to-income ratio and does not include interest.

Eleven numeric features are standardized. Seven categorical features are one-hot encoded with the first category dropped and unknown categories ignored by the transformer. The resulting artifact expects 26 transformed columns. API category validation is stricter than the transformer's unknown-category setting.

The preprocessor is fitted on the outer training partition. It is then applied before the calibration cross-validation step. This means preprocessing is not refitted independently within every calibration fold; a future training revision should place the full preprocessing pipeline inside cross-validation.

## Candidate models and selection

| Candidate | Main configuration | Validation ROC AUC | Validation average precision | Validation Brier |
|---|---|---:|---:|---:|
| Logistic regression | C=0.5, balanced classes, max_iter=1000 | 0.8133 | 0.4546 | 0.1687 |
| Random forest | 120 trees, depth 10, leaf minimum 5, balanced classes | 0.8164 | 0.4343 | 0.1380 |
| HistGradientBoosting | learning rate 0.08, 150 iterations, depth 6, leaf minimum 15 | 0.7994 | 0.4263 | 0.0816 |

The script explicitly selects HistGradientBoosting and applies sigmoid calibration through five-fold `CalibratedClassifierCV`. It does not automatically choose the highest-AUC candidate. HistGradientBoosting has the lowest recorded validation Brier score among these candidates, but claiming it wins every metric would be incorrect.

`pr_auc` in the metrics artifact is calculated as average precision. Keep that distinction when explaining the value; it is not necessarily trapezoidal area under a plotted precision-recall curve.

## Final held-out results

The calibrated saved model has test ROC AUC 0.7919, average precision 0.4023 and Brier score 0.0821. At probability threshold 0.20, precision is 0.362, recall 0.402 and F1 0.381. The confusion matrix contains TN=1460, FP=141, FN=119 and TP=80.

The threshold represents a configured policy with a 4:1 cost assumption in metadata, not a proven economically optimal decision boundary. The low/high band thresholds are 0.08 and 0.20. Human approval is separate from these classifications and is never inferred solely from a low band.

## Artifacts and startup validation

| File | Function |
|---|---|
| `ml/artifacts/riskora_model.joblib` | Fitted calibrated binary classifier |
| `ml/artifacts/preprocessor.joblib` | Fitted scaling and encoding transformer |
| `ml/artifacts/model_metrics.json` | Version, splits, evaluation, thresholds and reference summaries |

Startup requires all three nonempty files. It treats scikit-learn version mismatch warnings as errors, checks metadata thresholds and version, transforms a probe input, checks the transformed feature count and verifies a finite, normalized two-class probability output. The expected class order is `[0, 1]`.

These checks detect important compatibility failures but are not a cryptographic artifact-signing system. Only load artifacts from a trusted reviewed revision; joblib uses Python serialization and can execute code during loading.

## Inference and explanation sources

`backend/schema.py` normalizes API, database and scenario aliases. Missing values remain missing in stored profiles and quality reports. `inference_profile` applies documented fallbacks only when producing an inference input. A fallback-assisted assessment must not be presented as a fully verified borrower record.

`ml/infer.py` adds derived features, transforms the row, calls `predict_proba`, assigns a band and produces a display score. With PD p, low threshold L and high threshold H:

```text
p < L: score = round(30 * p / L)
L <= p < H: score = round(30 + 30 * (p - L) / (H - L))
p >= H: score = round(60 + 39 * min(1, (p - H) / (0.60 - H)))
final score = max(5, min(99, score))
```

The fixed rule points shown next to credit, DTI, employment and other factors are separate policy indicators. Their sum does not reconstruct the model score or probability. The saved coefficient list is from the logistic-regression baseline and does not explain the calibrated HistGradientBoosting model. ORA summarizes these sources without replacing the model band.

The dataset explorer uses its own labelled heuristic estimates. It should not be used to demonstrate exact model parity. For parity, compare a complete saved profile, the same direct analysis input and an unchanged scenario under the same artifact revision.

## Work before real-data use

Define the outcome and observation window, obtain lawful representative data, separate applicants chronologically, measure missingness and selection bias, compare against simple baselines and evaluate calibration by relevant subgroups. Refit preprocessing inside cross-validation, select thresholds against measured costs, add model-specific explanations and establish versioned approval and rollback procedures. Drift monitoring requires observed future inputs and outcomes; it is not currently operating in this prototype.

See [MODEL_CARD.md](MODEL_CARD.md) for the intended use and evaluation limits, and [DATA_DICTIONARY.md](DATA_DICTIONARY.md) for every input and fallback.
