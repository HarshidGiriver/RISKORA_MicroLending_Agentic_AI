# RISKORA input contract — first correctness milestone

`backend/schema.py` is the shared implementation for API input, saved records, data quality, anomalies, and inference. Field names below are canonical training-schema names. The API also accepts the documented camelCase and database snake_case aliases in `ALIASES`. Conflicting aliases for the same field are rejected. Override layers are normalized separately before merging.

These are demo input-validation bounds, not approved lending policy or verified-document checks.

| Field | Accepted values | Required to create a loan | Inference fallback if missing |
|---|---|---|---|
| Age | Integer 18–95 | No | 35 |
| Income | Finite number 1–5,000,000 | Yes | 450,000 |
| LoanAmount | Finite number 0.01–5,000,000 | Yes | 120,000 |
| CreditScore | Integer 300–850 | Yes | 650 |
| MonthsEmployed | Integer 0–948 | Yes | 36 |
| NumCreditLines | Integer 0–25 | Yes | 4 |
| InterestRate | Finite percentage 0–100 | Yes | 12.5 |
| LoanTerm | Integer 1–120 months | Yes | 36 |
| DTIRatio | Finite number 0–1.5 | Yes | 0.32 |
| Education | High School, Bachelor's, Master's, PhD | No | Bachelor's |
| EmploymentType | Salaried, Self-employed, Contract, Unemployed | No | Salaried |
| MaritalStatus | Single, Married, Divorced | No | Married |
| HasMortgage | Yes/No; boolean or 1/0 aliases accepted | No | No |
| HasDependents | Yes/No; boolean or 1/0 aliases accepted | No | No |
| HasCoSigner | Yes/No; boolean or 1/0 aliases accepted | No | No |
| LoanPurpose | Business, Education, Home, Auto, Other | No | Business |

Loan creation also requires a nonblank `name` of at most 200 characters. IDs are UUID-based and generated by the server. Missing optional profile values are stored as NULL, not silently fabricated. Categorical values are case-insensitive and normalized to the spelling above. Numeric booleans, NaN, infinity, invalid categories and non-integral integer fields are rejected.

`LoanID` and `Default` are not model inputs. The full CSV has 18 columns: 16 raw predictors, one ID and one target. Inference adds `LoanToIncome` and `MonthlyBurdenRatio`, then preprocessing encodes the 18 inputs into 26 features.

Data quality checks the eight required numeric fields and seven categorical fields for completeness; Age is validated when supplied but is not counted in the 15-field completeness score. Working-lifetime contradictions, unemployment/tenure conflicts and high DTI with zero credit lines trigger manual verification. Validity warnings also prevent `verification_ready`. Missing input remains visible in the quality response even when inference uses a fallback. Data quality means syntactic completeness/consistency, not documentary verification.

The model still supplies estimates for incomplete existing records and sandbox requests. A saved case requiring verification is moved to NEEDS_VERIFICATION only while in an early review stage; a funded/repaying case's workflow status is preserved. Blocking final approval and enforcing human-review transitions are later milestones.
